Map key — base component (im-c-map-key)

A flat key with three pattern-fill items, mirroring the field-parcel sublayers in demo/DemoMapPolygons.js. This is a duplicated snapshot of KeyItem + KeySvgPattern's output and of the production stylesheet, as corrected on the (unmerged) IM-482 branch — each item is a plain im-c-map-key-list__item, not its own <dl> — see map-key.scss and the project README.md for the duplicate → approve → port-back workflow. Not imported from plugins/map-key, so it's safe to edit here freely.

Map key ramp — horizontal presentation

Not a new component after all — im-c-map-key-list--ramp-horizontal is a modifier on the standard key/group/item, matching KeyGroupItem.jsx's real groupStyle → im-c-map-key-list-<groupStyle> convention on the IM-482 branch (the same branch that also fixes the group's items to share one <dl> — see the specimen above), corrected here to a proper double-hyphen BEM modifier — every other modifier in this codebase is double-hyphen (im-c-map-key--has-groups, im-c-map-key-symbol--point) — and given an orientation suffix, since a vertical ramp turns out to need its own ruleset too (symbols stretched vertically to butt against each other), not just the standard list. Laying the same dt/dd items out as an equal-width row instead of a block-stacked column. Sample data is 7 items labelled 1-7; the layout works for anywhere from 3 to 7. Colours are a single-hue sequential ramp, verified with the dataviz skill's validate_palette.js --ordinal. No viewBox on the symbol SVGs — see map-key-ramp.scss for why that matters once patterns/strokes are involved, and for how this differs from that branch's own (solid-fill-only, grid/RTL-based) WIP ramp CSS.

Map key ramp — Risk example

Same mechanism as the ramp above, three bands (Low/Medium/High) using the dataviz skill's fixed status palette (good/warning/critical), not literal green/yellow/red — those exact steps are already contrast-validated for state communication like this. Each band reuses one of the same three DemoMapPolygons patterns as the map-key specimens (horizontal-hatch/diagonal-cross-hatch/dot), so this tests the ramp's border, rounding, and hatching together. Border stroke is the same colour as the band's own pattern on light backgrounds — matching the real DemoMapPolygons sublayers, whose stroke and pattern foreground are the same value — at 2px, matching KEY_BORDER_PATH's own stroke-width; flips to white on dark backgrounds.
